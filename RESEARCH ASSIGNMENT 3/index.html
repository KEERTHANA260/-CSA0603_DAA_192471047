Q1 · 6 marks

Decomposition and elimination in ordered data

Max/Min splits the array in half, solves both halves, then combines with two comparisons. Binary search throws away half the range after each comparison.

T(n) = 2T(n/2) + 2 → 3n/2 − 2 comparisons
T(n) = T(n/2) + 1 → ⌊log₂ n⌋ + 1 comparisons
Q2 · 7 marks

The quality of decomposition in sorting

Quick Sort here uses the last element as pivot (Lomuto partition). A sorted input makes every split n−1 : 0, so the recursion tree becomes a chain. Merge Sort always splits in the middle.

Balanced: T(n) = 2T(n/2) + n → Θ(n log n)
Worst: T(n) = T(n−1) + n → Θ(n²)
Q3 · 7 marks

Breaking the quadratic barrier: Karatsuba

Write x = a·10ᵐ + b and y = c·10ᵐ + d. Instead of four half-size products, compute ac, bd and (a+b)(c+d), and recover ad + bc by subtraction. That is three recursive multiplications, so T(n) = 3T(n/2) + cn = Θ(n^1.585).

Extra additions and shifts cost something at every call. Set that cost below and watch where Karatsuba starts to win.

Q4 · 7 marks

The reality of Strassen’s multiplication

Seven block products instead of eight, but 18 block additions per level. Matrices that are not a power of two are padded up, which can cost almost 8× the work.

T(n) = 7T(n/2) + Θ(n²) → Θ(n^2.807)
Q5 · 6 marks

Closest pair by divide and conquer

Sort by x, split at the median, solve both sides, then only check points within δ of the dividing line, and only against nearby points in y-order.

T(n) = 2T(n/2) + Θ(n) → Θ(n log n) versus n(n−1)/2
Q6 · 7 marks

Advanced investigations

Median of Medians. Groups of five guarantee that the pivot discards at least about 3n/10 elements, so T(n) ≤ T(n/5) + T(7n/10) + cn = Θ(n). A deterministic first-element pivot on sorted data discards one element per round.

Meet-in-the-Middle subset sum. Split the items in two halves, list the 2^(n/2) sums of each, then search one list for the complement of each sum in the other. Time falls sharply; memory grows.

Design divide and conquer from first principles

Work through the six stages in order. Both partners propose independently before talking, and both must be able to defend every stage.

    Before choosing divide and conquer, check for: independent subproblems of the same kind, a trivial base case, a cheap combine step, balanced splits, and a recurrence that beats the straightforward method. Overlapping subproblems point to dynamic programming instead.
